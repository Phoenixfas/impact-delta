## Architecture

Single-page marketing site (App Router, `app/` directory) for "IMPACT B2B", a corporate event/summit platform. Everything renders through one route: `app/page.tsx`, which composes `Navbar` plus six section components from `components/` in order — `HeroSection`, `AboutSection`, `AchievementsSection`, `ProjectsSection`, `ServicesSection`, `ShowreelSection`.

### Root layout & cross-cutting providers

`app/layout.tsx` loads Geist/Lobster fonts, sets global metadata, and nests three always-mounted client providers around `{children}`: `RevealProvider` > `KineticBackground` + `SmoothScroll`. All three matter for anything rendered on the page:

- **`components/RevealProvider.tsx`** — a small context (`useReveal()` → `{ revealed, setRevealed }`) whose only job is letting components outside `HeroSection`'s tree react to its entrance-animation state. `KineticBackground` needs this because it's mounted as a *sibling* of the page content in the root layout, not a descendant of `HeroSection` — there's no prop-drilling path between them, so a shared context is what bridges "hero entrance finished" to "fade the background in now."
- **`components/SmoothScroll.tsx`** — wraps the app in a Lenis smooth-scroll instance synced to GSAP's ticker/`ScrollTrigger` (Lenis drives scroll position, GSAP scroll-triggered animations stay in lockstep). Exposes `useSmoothScroll()` → `{ lenis, scrollTo }`. Use `scrollTo` instead of `window.scrollTo`/`scrollIntoView` for any in-page navigation so it respects the smooth-scroll physics and header offset; use `lenis?.stop()`/`lenis?.start()` to freeze background scroll while a fullscreen modal/lightbox is open (see `HeroImageLightbox`, `ShowreelSection`, `ProjectsSection`'s case-study modal).
- **`components/KineticBackground.tsx`** — fixed, `-z-10`, `pointer-events-none` canvas covering the viewport. Runs its own rAF loop (independent of GSAP/Lenis) rendering ambient gradient blobs, a pointer-reactive particle lattice with autonomous "network pulse" bursts (nodes self-illuminate and link up periodically, independent of the cursor), and floating dust. Stays at `opacity-0` until `useReveal().revealed` flips true (set by `HeroSection` once its own entrance timeline completes), so the canvas isn't visible while the hero's particle-reveal intro is still playing — the simulation keeps running underneath while hidden so it's already "warm" the moment it fades in.

### Navbar and section IDs

`components/Navbar.tsx` is a fixed pill-shaped header (logo, menu trigger, CTA) whose three nodes drift toward the cursor via a small spring-physics loop, connected by an SVG constellation line. `NAV_ITEMS`/`NAV_LINKS` entries are hash links resolved by `scrollTo`; the target `id`s live on the `<section>` roots of the components in `page.tsx` (e.g. `HeroSection` → `#hero`, `ProjectsSection` → `#portfolio`). **Adding or renaming a section is a three-touchpoint change**: create the section component, mount it in `app/page.tsx`, and add/update its entry in `Navbar.tsx`'s `NAV_LINKS` — the nav and the actual section `id` will silently drift apart otherwise. Not every nav entry currently resolves to a mounted section (e.g. `#stage` targets `HeroConstellation` inside `HeroSection`, `#contact` has no section yet but is already used as a scroll target from CTAs elsewhere) — this is an established, intentional pattern in this repo: CTAs/nav are pre-wired to where a section *will* live before it's built.

The mobile/fullscreen menu overlay is always mounted (not conditionally rendered) so its close animation can play: it reveals via a `clip-path: circle()` growing from an invisible dot at screen-center to full coverage, driven by GSAP, not by mount/unmount.

### Section component conventions

Every section component that runs GSAP registers its own plugins and owns its own cleanup — `gsap.registerPlugin(ScrollTrigger, ...)` + `gsap.context(() => {...}, sectionRef)` + `return () => ctx.revert()` in a single mount effect. This is the established pattern for new animated sections, not a shared/global timeline. `ShowreelSection` additionally registers `Flip` (`gsap/Flip`, bundled with the installed `gsap` package) for its card-to-fullscreen morph.

Scroll-triggered reveals key off **CSS class hooks** registered inside that `gsap.context()` (e.g. `.bento-card-border` in `AchievementsSection`, `.service-row` in `ServicesSection`, `.showreel-heading`/`.showreel-card-wrap`/`.showreel-stat` in `ShowreelSection`, `.projects-header-item` in `ProjectsSection`) rather than iterating refs — new sections wanting scroll reveals should follow the same convention.

**Above-the-fold vs below-the-fold reveal state matters.** `HeroSection`'s entrance-choreographed elements (`.hero-split-word`, `.hero-stack-card`, `.nav-entrance-node`, etc.) are given their *hidden* state directly in `app/globals.css`, not only via a `gsap.set()` in a `useEffect` — a JS-only hide runs after the browser's first paint, so anything visible in the server-rendered HTML flashes visible-then-hidden before the reveal plays. Sections below the fold (Achievements, Services, Showreel, ...) don't need this: by the time a user scrolls to them, hydration is long finished, so a plain `gsap.set(...)` inside the mount effect is sufficient.

### Recurring interaction patterns

Several sections re-implement the same handful of primitives — reuse these rather than inventing new ones:

- **Cursor-following floating elements**: `gsap.quickTo(el, "x"/"y", {...})` driven by `pointermove`, with position math kept on a *different* DOM node than any CSS-driven centering transform (`-translate-x-1/2 -translate-y-1/2`) so GSAP's transform writes never clobber it. Used for the Services floating image preview, the Showreel cursor "PLAY" badge, and the Projects horizontal-track drag pill.
- **Native-cursor hiding must be CSS `:hover`-driven, not React-state-driven.** A React `isHovering` boolean gating `cursor-none` can go stale exactly when an element's layout changes under a stationary pointer (e.g. after a GSAP Flip transition) — no new `pointerenter` fires just because the box moved, so the cursor can stay hidden with nothing drawn in its place. `ShowreelSection`'s `.showreel-hover-none:hover { cursor: none; }` plus `group-hover:opacity-*` for the custom badge fixes this by relying on the browser's own live hover recomputation.
- **Animated count-up counters**: tween a plain `{ value: 0 }` object to its target with `ScrollTrigger` (`once: true`), writing the formatted string to a ref'd span's `textContent` in `onUpdate`. Used in `AchievementsSection` and `ShowreelSection`.
- **Scroll-linked parallax on images**: wrap the `<Image fill>` in an inner div with vertical bleed (`-inset-y-[X%]`) and scrub that wrapper's `yPercent`/`scale` via `ScrollTrigger`, keeping any separate hover-zoom (`group-hover:scale-*`) on the `Image` itself so the two transforms never compete for the same element's `transform` property.
- **GSAP Flip layout morphs**: capture `Flip.getState(el)` synchronously in the click handler *before* the state change that alters layout, then re-apply it via `Flip.from(state, {...})` inside a `useLayoutEffect` keyed on that state (so it runs after React has committed the new DOM/classes but before paint). See `ShowreelSection`'s compact-card ↔ fullscreen-lightbox morph.

### Assets

`public/images/` (plus `public/images/prev/`) holds the real photography used across sections — images are deliberately reused between sections (e.g. `summit-keynote.jpg` appears in Hero, Achievements, and Showreel) rather than sourced uniquely per section. `render2.webp`/`cutout_left.webp`/`cutout_right.webp` are generic "Lorem Ipsum" placeholder renders and aren't used as real content anywhere. There are no video assets in the repo; `ShowreelSection` embeds a placeholder YouTube video (Big Buck Bunny) until a real showreel file/link is supplied.

## Styling

Tailwind CSS v4 (via `@tailwindcss/postcss`, no `tailwind.config.*` — config lives in `app/globals.css` using `@import "tailwindcss"` + `:root` custom properties). The brand palette, gradient, border, and diffused-shadow tokens are all defined there — reuse those CSS variables (`--primary`, `--secondary`, `--tertiary`, `--shadow-diffused-*`, `--gradient-corporate`, etc.) rather than hardcoding new colors/shadows. Notable reusable utility classes built on top of those tokens: `.glass-card`/`.glass-card-subtle`/`.glass-card-elevated` (glassmorphism panels), `.bento-card-border`/`.bento-card-inner` (gradient-border + ambient-inset-shadow bento cells), `.text-gradient` (brand blue→cyan text clip, for light backgrounds) and `.text-gradient-light` (white→cyan, for sections whose own background *is* the brand gradient — `.text-gradient` would blend into it there).

Icons: `lucide-react`. Animation: `gsap` (with `ScrollTrigger` and, where needed, `Flip`) for scroll/reveal/layout choreography, `lenis` for scroll physics — both are already initialized globally, don't re-instantiate per component.
